# 故事分岔 · AI 互動故事工作流 v1.0

多結局文字冒險編輯器。繁體中文、手機適用、無 API 金鑰、無外部程式庫。使用你選擇的 AI 生成故事 JSON，再匯入網頁與素材繼續修改。

## 最快開始
1. 解壓縮，開啟 `Story_Fork_Editor.html`；這是已打包的單檔編輯器。或開啟根目錄 `index.html`（旁邊的 JS / CSS 必須保留）。
2. 點「從頭試玩」體驗《雪線以外》。這是四結局、二周目原創短篇示例，約 3–5 分鐘，不是完整長篇遊戲。
3. 切到「專案 / AI」，下載 AI 生成 MD，填入你的故事要求並交給 AI。
4. 匯入 AI 輸出的 `.json`，或含第一個完整 JSON 程式碼區塊的 `.md`。
5. 批次匯入圖片、影片、音樂；素材庫會按完全相同的檔名對應。沒有對應時會新增素材 ID，請在場景裡指定。
6. 編輯場景、選項與條件，執行「檢查故事」，並實際試玩每個結局。
7. 輸出 JSON / MD 備份；輸出遊戲 HTML 或 GitHub 遊戲 ZIP 供玩家遊玩。

## 編輯功能
- 新增、複製、刪除節點；修改節點 ID 會更新 target 引用及開始節點。
- 修改標題、章節短標、文字、背景圖片或靜音循環影片、背景音樂及單次音效。
- 新增、刪除、排序選項；設定目標、條件、變數效果。
- 設定多個結局。首次通過結局即保留結局 ID；以 `ending.good == true` 解鎖二周目路線。
- 修改結局 ID 會更新相關條件。刪除結局節點後，若仍有條件引用它，檢查會提示，需手動決定新規則。
- 分支關係總覽、文字搜尋、即時場景預覽、從目前節點測試、18 步復原 / 重做。
- 圖片 / 影片 / 音訊批次匯入，依檔名對應；個別替換保留 ID；刪素材同步清除場景引用。
- 匯入 / 輸出 JSON、可重新匯入的 MD；可下載包含目前專案的 AI 修改 MD。

## 選項條件與效果
- 在「專案 / AI」定義變數初值，例如 `{"warmth":1,"hasKey":false}`。
- 每一輪的變數都從初值開始；結局紀錄跨輪保留。
- 條件是 AND；全部成立才可選。支援 `== != > >= < <=`，大小比較僅限數字。
- `round` 是第幾輪；`ending.結局ID` 表示是否已發現此結局。
- 選項的 set 效果先執行，接著執行數值 add；使用 `-2` 可扣除兩點。
- 條件文字值寫 `"文字"`，布林寫 `true` / `false`，數字寫 `2`；避免把數字誤寫成字串。
- 沒有可用選項時，播放器會明確顯示錯誤，不會假裝是結局。
- 「從此節點測試」使用變數初值，保留此專案已解鎖的試玩結局；不模擬抵達該節點之前的選擇效果。

## 素材與匯出
| 匯出 | 是否包含素材 | 適用情況 |
| --- | --- | --- |
| JSON / 專案 MD | 已載入檔案以 data URL 內嵌；外部網址保留 | 備份、移到另一台電腦繼續編輯 |
| 遊戲 HTML | 程式、故事、已載入素材都在同一檔案 | 離線單機、小型遊戲 |
| GitHub 遊戲 ZIP | 素材拆到 assets，故事和播放器程式內嵌 index.html | 較多素材、較大音樂與影片 |
| AI 修改 MD | 刻意省略素材 data，保留 ID / name / src | 減少交給 AI 的內容量，不是素材備份 |

- AI 修改結果匯回原專案時，若專案 ID、素材 ID、類型、檔名與來源保持相同，會沿用編輯器已載入的素材。換瀏覽器或資料已清除時，需重新載入素材。
- 不會自動下載遠端素材。來源為 URL 時仍需連線與有效權限；請優先匯入有權使用的本機素材。
- 影片預設靜音、循環、鋪滿背景；需要影片原音時，另準備音訊檔。頁面載入不自動發聲，玩家開始或操作後才播放；失敗時可點「重試音訊」。
- 常見圖片 PNG / JPG / WebP / SVG、影片 MP4 / WebM、音樂 MP3 / WAV / OGG；能否解碼取決於瀏覽器。iOS、Android、桌面瀏覽器請實機測試。
- 單檔匯入上限 150 MB；大量影片不適合內嵌 HTML。ZIP 採不壓縮封裝，已壓縮素材不必再壓，並非 ZIP64。
- 上傳 GitHub 之前注意當時平台的檔案大小限制與儲存庫配額。

## 放到 GitHub Pages
此套件已準備好靜態網站檔案；不會自動建立 GitHub 儲存庫或部署。

### 發布編輯器
1. 將解壓後根目錄的檔案上傳儲存庫，保留 `index.html` 與相鄰的 JS / CSS / MD / JSON。
2. GitHub 儲存庫 → Settings → Pages → 選擇以分支發布，選取該分支與根目錄後保存。
3. 開啟 GitHub 提供的網址。所有編輯資料仍留在訪客瀏覽器；上傳素材不會自動寫回儲存庫。

### 發布遊戲
在編輯器輸出「GitHub 遊戲 ZIP」，解壓後將其中 `index.html`、`assets/` 與其他內容放到另一個儲存庫或子資料夾，再設定 Pages。

遊戲 ZIP 的 `story.json` 是提供編輯器重新匯入的來源；播放器已把相同資料內嵌在 HTML。手改 story.json 不會自動改變遊戲，請重新匯入、輸出。JSON 內的素材 name 會改成拆分後檔名，方便再次載入。

## 草稿與玩家存檔
- 編輯草稿以 localStorage 保存；常見容量只有數 MB，超出會提示。大型專案一定要輸出 JSON / MD。
- 草稿自動保存不代表已下載備份；離開仍會提示尚未輸出的修改。
- 玩家進度與編輯草稿分開。玩家可下載 / 讀取 JSON 存檔；已到達結局也會自動保存。
- 「從頭試玩」開始新一輪並保留結局；「繼續」或重新開啟遊戲可還原最近進度。清除紀錄會刪除所有已解鎖結局。
- file:// 儲存行為依瀏覽器而異；手機可直接測試線上的 GitHub Pages。
- 改動變數型別、刪除結局或大幅改寫故事時，建議更新專案 ID。下載舊存檔後再清除紀錄，可避免衝突。

## 檢查與限制
內建檢查涵蓋 JSON 結構、重複 ID、不存在的目標、素材類型、變數型別、未知結局及無法到達的節點。不能取代每個數值狀態的實際通關測試；AI 指引要求列出每個結局的通關路徑。

核心自動測試可執行 `node tests/core.test.cjs`，無需安裝依賴。此環境未能啟動瀏覽器檢查介面，因此手機版視覺排版與實際影音解碼仍需在你的裝置確認。

目前沒有時間限制選項、雲端同步、帳號、AI API 串流、多人遊戲、隨機與戰鬥系統。匯入文字按純文字處理，不執行 HTML / JS。
